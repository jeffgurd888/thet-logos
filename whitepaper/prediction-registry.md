## Protocol

Each entry is exactly five fields, all present, all filled before
the analogue runs:

1. **Analogue system** — the physical or simulated analogue the
   prediction concerns, named specifically enough that an outsider
   could run the same system.
2. **Quantity predicted** — the exact quantity, with its definition
   and units; no quantity, no entry.
3. **Value or range predicted** — the sharp, falsifiable value or
   range. A prediction that every outcome confirms is not a
   prediction and is not registrable.
4. **Date registered** — the date the entry was written here. The
   entry is valid only if this date precedes the run it concerns.
5. **Kill reading** — the result that retires the entry. Every
   entry carries its own kill condition on its face, stated before
   the run, in the same terms as field 2.

**Grading.** An entry is graded only by an external confirmation:
a measurement of the registered quantity, on the registered
system, by a party other than the house, reported against the
registered value/range. Outcomes are appended to the entry as a
dated grading note — never edited into fields 1–5.

## Kill rule K-BR3 (verbatim in effect)

Any prediction edited after its analogue ran is void on its face
and is logged as void — never silently corrected. A voided entry
stays in this file, marked VOID with the date and reason; it is
not deleted, not repaired, and not re-registered under a fresh
date for the same run. A genuinely new prediction about a future
run is a new entry.
